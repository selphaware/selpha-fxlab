# T1 — Coverage survey (Dukascopy, 12 pairs, 2005-01-01 → 2025-02-28)

Bounded loop task. Scope is this card; the agent may not extend it.

## Question

For each universe pair: from which date is Dukascopy tick coverage reliable
enough to research on, and where are the material holes between that date and
2025-02-28?

## Method (probe, don't ingest)

* Sampling probe, not bulk download: for each pair, request ONE liquid hour
  per trading day (13:00 UTC) across the range. Classify each probe:
  `data` (200, decodable, >0 ticks), `empty` (200, 0 bytes), `missing` (404),
  `error` (retries exhausted). Record compressed size and tick count for
  `data` probes; decode to count ticks but DO NOT store tick Parquet — probe
  results go to a JSON/Parquet summary under `experiments/T1-coverage/`.
* Refine boundaries: where a pair transitions from missing/empty to data
  (earliest coverage) or shows runs of ≥5 consecutive non-data trading days,
  bisect with additional probes (any hour 08:00–16:00 UTC) to date the
  boundary or hole to within a week.
* Sanity: for 3 probes per pair spread across the range, decode fully and
  check spread sanity (ask ≥ bid > 0, spread below the Phase 1 ceilings) —
  early-history data quality, not just presence.
* Network discipline: ≤2 concurrent connections, exponential backoff per the
  Phase 1 client, resumable (probe results checkpointed so a rerun skips
  completed probes). Expect hours of wall clock; that is budgeted.
* Seal: no request may name a date ≥ 2025-03-01. The probe date range is
  [2005-01-01, 2025-02-28] and the gate will check the configs.

## Deliverable

`reports/T1_coverage.md` containing, per pair: recommended research start
date with the evidence (first sustained coverage, probe density around it);
a table of material holes (≥5 trading days) with dates and sizes; probe
counts by classification; the 3-probe data-quality spot checks; and a
closing section "What this bounds" — which pairs support how many years of
which timeframes, and any pair whose coverage argues for dropping or
shortening it (a checkpoint decision, flagged not made).

Plus `experiments/T1-coverage/` with config, probe results, result.json,
ledgered per protocol (mechanical/non-scorable — this is a data survey).

## Non-goals

No tick storage, no bar building, no EDA, no strategy content, no universe
membership changes (flag, don't decide), no requests past the seal, no
changes to fxlab/ or research/ beyond what probing strictly requires (if a
probe helper is needed, it lives in research/, gated as usual).
